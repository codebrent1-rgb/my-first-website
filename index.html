Layered Overview

从核心能力到工程系统的三层图谱

Codex 不是单一聊天框，而是一组跨本地、云端、IDE、CI 和团队工具的开发能力。页面将它拆成“做什么”“在哪里做”“如何扩展与治理”。

01

核心开发能力

面向代码本身：生成、理解、调试、测试、重构、审查和解释复杂代码库。

  • 按项目结构和约定生成代码
  • 阅读遗留系统并解释组织方式
  • 定位缺陷、补测试、验证结果
02

多入口工作形态

同一个编码代理可以在桌面 App、终端、IDE、Web 和云任务中工作。

  • 本地线程、Worktree 和内置终端
  • IDE 上下文、云端委派和 PR 跟进
  • CLI 交互、非交互、远程连接
03

扩展、自动化与治理

用 Skills、Plugins、MCP、Hooks、权限和沙箱把 Codex 接入团队流程。

  • 后台自动化、GitHub Action、SDK
  • AGENTS.md、Memories、Subagents
  • 审批、网络策略、企业管理配置

Workflow

从想法到合并的一条典型路径

Codex 的强项在于把“理解、修改、验证、审查、协作”串成闭环。每一步都可以停下来让人审阅，也可以按权限配置自动推进。

1

给出目标

用自然语言描述要实现、修复或理解的问题，必要时附上截图、日志或文件引用。

2

读取上下文

Codex 结合仓库、AGENTS.md、IDE 当前文件、MCP 或插件信息建立任务视野。

3

执行修改

在 Local、Worktree 或 Cloud 环境中编辑文件、运行命令、补充测试并验证结果。

4

审查反馈

通过 Review 面板、/review、GitHub PR 评论或浏览器批注聚焦风险与细节。

5

交付或自动化

提交、推送、创建 PR，或把流程沉淀成 Skill、Automation、Action 或 SDK 调用。

Safety & Governance

让代理能工作，也能被约束

Codex 的安全模型由技术边界、审批策略、网络访问和组织治理共同构成。页面中所有高权限能力都应按最小必要范围启用。

沙箱边界

本地命令运行在受限环境中，常见模式包括 read-only、workspace-write 和 full access。默认应优先让任务留在工作区边界内。

  • 限制写入目录
  • 限制或关闭命令网络访问
  • 越界时进入审批流程

审批与自动审查

Approval policy 决定 Codex 什么时候暂停请求许可；可用时，自动审批 Review 能对部分请求做风险判断。

  • 用户审批是默认路径
  • 自动审查不改变沙箱边界
  • 高风险和破坏性动作要谨慎

企业与团队治理

组织可用 managed configuration、管理员策略、审计日志、数据保留和访问控制约束 Codex 的使用范围。

  • 限制可用权限模式
  • 管理网络与工具策略
  • 集中配置与合规审计
